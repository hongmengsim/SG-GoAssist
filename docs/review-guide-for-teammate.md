# Review guide for the backend and app owner

**Purpose.** Between commit `13acadc` and now (87 commits, 147 files, about 11,500 lines added) CE2 changed how the backend stores data, locks, publishes events and authenticates devices. The passenger app and the message contracts are **not** changed (the app has one test-configuration line, `jest.setup.ts`; `contracts/` has one README line). This page says what changed, where to look first, what to check, and what has not been tried. It is written for a reviewer who owns the original backend and app.

**What is verified and what is not.** The backend has 521 tests, all passing, including the Postgres tests against a real Postgres (the CI job `postgres-redis` runs them too). Two real backend processes sharing Postgres and Redis pass `npm run check:multi-process` and the two-process end-to-end scenario. Nothing has been run on more than one machine, nothing has been load-tested beyond one machine, and no hardware has been involved in the backend tests.

## 2. Where to look hardest

1. **Lock use in `assistanceCaseService.ts`.** Every case operation runs under `case-service` (one lock for all cases). Check that no read-modify-write of a case happens outside it, and that nothing that holds it waits for an external call. It is re-entrant, so a function that holds the lock may call another that takes it.
2. **`compareAndUpsert` in `busOperations/`.** Repeat and stale bus reports are written without a lock using a compare-and-swap, and fall back to the locked path. Read `busReports.ts` and `busOperationsService.ts` with `tests/busReportRace.test.ts`.
3. **The signing change in `auth.ts`** and the rule that the operator-only routes above need the token.
4. **`legacyImport.ts`**, which inserts old data only where nothing exists.

## 3. How to check it yourself

```
npm install --workspace @buspass/shared --workspace @buspass/backend
git checkout -- package-lock.json      # a partial install rewrites the lockfile
npm test --workspace @buspass/backend  # 521 tests (45 skip without Postgres)
npm run verify:fast                    # typecheck, format, module boundaries, tests
```

With Postgres and Redis installed: `npm install --no-save --workspace @buspass/backend pg ioredis`, set `GOASSIST_TEST_DATABASE_URL`, rerun the backend tests, then `npm run check:multi-process` with `GOASSIST_DATABASE_URL` and `GOASSIST_REDIS_URL` set (see `docs/runbooks/multi-process.md`).

## 4. Questions for you

- Does the passenger app call any of the routes that now need the operator token (other than telemetry)? If it does, tell us which and we will give it a passenger-scoped route instead.
- Are the retention defaults acceptable, or should finished cases be kept longer?
- The passenger routes still have no per-request secret (a request id is unguessable now, but anyone holding it can read or cancel that request). Should the app send a per-request token?
- Alighting and destination scope in the app, an open question since the handoff: the app is unchanged, and the mismatch is recorded for the report.

## 5. Not built, so you do not look for it

Signed WebSocket pushes (the Pi accepts a pushed halt but never a pushed release), a replay cache shared between processes, individual operator tokens, per-stop lock keys (one global case lock is used), archiving under Postgres to a table (the archive is a local file), and anything on real hardware. `deploy/` holds a Dockerfile and compose file that have never been run.
