# Reviews of 1 Oct 2026: security, backend code, Pi agent, operator console

Four independent read-only reviews of the work since commit `13acadc` (the storage, async, lock, event-bus and Postgres changes, the Pi bus agent, and the operator console). Each reviewer read the code; **none of the findings below has been reproduced by running it** unless the status says so, and nothing was changed as a result of the reviews yet. Status of every item is **open** until it says otherwise.

How to read the columns: "Cause" says whether the finding comes from this stretch of work ("new"), was already in the code ("existing", mostly the passenger and simulator routes the project started with), or is a design gap. Severity is the reviewer's, with the reviewer's own uncertainty kept in the text.

Nothing in the Pi or console reviews or the security review was rated CRITICAL. The Pi safety gate itself was found fail-safe (details at the end).

## Security review (backend)

| ID    | Severity | Cause    | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Status |
| ----- | -------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| S-H1  | HIGH     | new      | Handlers turned `async` by the conversion (`routes/assistance.ts`, `/health`, `routes/assistantDiagnostics.ts`) have no try/catch, and Express 4 does not catch rejected promises. A database blip or a `LockTimeoutError` becomes an unhandled rejection, and Node exits. Fix: wrap async handlers like `busOperations.ts` `handle()`, and log unhandled rejections.                                                                                                                                                                    | open   |
| S-H2  | HIGH     | existing | `/api/assistance/simulator/command` and `/simulator/vehicle`, `GET /api/assistance/`, `POST /:id/cancel` and `GET /:id` need no auth. With auto-acknowledge on (the default) anyone can forge "confirmed by bus"; anyone can fail or cancel any request. Request ids have only 24 random bits. Fix: operator-only or disabled in production; a per-request secret; `randomUUID` ids.                                                                                                                                                     | open   |
| S-H3  | HIGH     | existing | If `OPERATOR_API_TOKEN` or `DEVICE_SHARED_SECRET` is unset, every operator route, `/admin/reset`, device routes and both WebSocket subscriptions are open, with no start-up guard. Fix: refuse to start in production, or with a database or Redis configured, unless both are set.                                                                                                                                                                                                                                                      | open   |
| S-H4  | HIGH     | existing | `GET /api/operations/cases`, `/cases/:id`, telemetry, autonomy and capabilities routes and `POST /cases/:id/feedback` need no auth; cases include `anonymousToken`. Fix: operator auth, or scope by a passenger token.                                                                                                                                                                                                                                                                                                                   | open   |
| S-M1  | MEDIUM   | new      | The rate limiter keys on the unauthenticated `x-device-id` header (rotate it for a fresh burst) and unsigned traffic to `/vehicles/...` is classed "safety" and never shed. Fix: key unverified traffic by IP; class as safety only after the signature verifies.                                                                                                                                                                                                                                                                        | open   |
| S-M2  | MEDIUM   | existing | The device signature does not bind method, path or bus; every bodyless request signs the same `{}`; `x-device-id` is not checked against `:busId`; one shared secret; no nonce. A sniffed signature replays against any such endpoint for 60 s. Fix: sign method, path, timestamp and body; per-device secrets; nonce cache.                                                                                                                                                                                                             | open   |
| S-M3  | MEDIUM   | existing | `verifyDeviceRequest` accepts a non-numeric timestamp (`Math.abs(now - NaN)` is not greater than the window). Needs the secret to exploit. Fix: `Number.isFinite`.                                                                                                                                                                                                                                                                                                                                                                       | open   |
| S-M4  | MEDIUM   | existing | Secrets compared with `!==` (operator token, WebSocket token, diagnostic deletion token). Fix: `timingSafeEqual`.                                                                                                                                                                                                                                                                                                                                                                                                                        | open   |
| S-M5  | MEDIUM   | existing | Passenger WebSocket subscriptions accept arbitrary bus, request and case ids (watching another passenger's updates); no `maxPayload` (ws default is 100 MiB), no length checks, no per-IP connection cap. Fix: derive subscriptions from what the client owns; set `maxPayload` near 4 KB; validate lengths.                                                                                                                                                                                                                             | open   |
| S-M6  | MEDIUM   | new      | All case operations share one lock (`case-service`), reachable by unauthenticated `POST /request`, `/passenger-help` and `/feedback`; under the database lock waiters fail after 10 s (a 500, or a crash per S-H1), and operator case actions queue behind them. Fix: per-stop or per-case keys; cap queue depth.                                                                                                                                                                                                                        | open   |
| S-M7  | MEDIUM   | new      | The diagnostics endpoint scans, parses and deletes up to 50,000 rows per POST and stores the deletion token in plaintext. Fix: purge on the retention timer with one SQL `DELETE ... WHERE expires_at`; store a SHA-256 of the token.                                                                                                                                                                                                                                                                                                    | open   |
| S-M8  | MEDIUM   | new      | The Postgres pool has no `error` listener (an idle client dying on a database restart is an uncaught exception) and no connection, statement or idle timeouts. Fix: `pool.on("error", ...)` and timeouts.                                                                                                                                                                                                                                                                                                                                | open   |
| S-M9  | MEDIUM   | new      | `cases-archive.ndjson` holds full cases (including `anonymousToken`) forever, default file mode, defeating the 7-day retention, even when Postgres is used; audit `appendFileSync` blocks the event loop. Fix: mode 0600, rotate or prune the archive, strip the token.                                                                                                                                                                                                                                                                  | open   |
| S-M10 | MEDIUM   | new      | `/ready` returns `String(error)` from database failures (host, port, user). Fix: return "failed", log the detail.                                                                                                                                                                                                                                                                                                                                                                                                                        | open   |
| S-L   | LOW      | mixed    | Halts are attributed to a shared token, not a person (L1); replayable `SUBSCRIBE_DEVICE` signature for 60 s (L2); the throwaway CI service password `ci-only-password` is in the workflow (L3, acceptable, do not reuse); Redis content is trusted, so Redis needs AUTH and TLS (L4); `NODE_TEST_CONTEXT` set in production would disable rate limiting and the database URL (L5); no Host check or socket timeout on the Pi status page (L6); the fixed advisory-lock id 727001 is shared with any other app on the same Postgres (L7). | open   |

Sound (per the reviewer): no SQL injection (every value is `$n` or `?`, interpolated identifiers are validated constants, the schema name is validated); the advisory lock and the lease statements; the event bus cannot cross into `op:` topics and its dedupe map is bounded; no committed secrets; the database URL is not logged; `legacyImport` reads a local trusted file only; bounds on audit, reports and diagnostics inputs.

## Pi bus agent review

| ID   | Severity | Cause    | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Status |
| ---- | -------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| P-H1 | HIGH     | new      | A stale cached operator-halt poll can release a halt that a WebSocket push just set: `_pull_halt` overwrites the flag with a cache that is 0 to 10 s old. Fix: version or timestamp the poll result and never let a poll clear a halt set after that poll's fetch; refresh on demand.                                                                                                                                                                                     | open   |
| P-H2 | HIGH     | new      | The link-loss halt cannot fire if the worker thread is stuck (a call blocked beyond the socket timeout), dead (`http.client.HTTPException` subclasses are not caught, so the thread dies silently) or has never tried: `last_error` stays None and the link counts as healthy. Fix: record the time of the last success and treat none within N s (or a dead worker) as link lost; catch everything in `_run` and `_call`.                                                | open   |
| P-H3 | HIGH     | new      | `arrive()` sets the bus POSITIONED before the backend answers; on a timeout it stays POSITIONED, and a later 409 refusal is dropped, so the bus never moves to WAITING and the `WAITING_FOR_BAY` reason never appears. Fix: on a timeout set WAITING until entry is granted; surface refusals from the async path.                                                                                                                                                        | open   |
| P-M1 | MEDIUM   | new      | Nothing catches an exception from `tick()`: an unplugged ESP32, a non-dict backend item or a malformed push ends the process (fail-stop, no final halt report). Fix: turn sensor read errors into UNKNOWN or no frame; validate items; wrap `step` so an error forces HALT and the loop continues.                                                                                                                                                                        | open   |
| P-M2 | MEDIUM   | new      | After a Pi restart during an operator halt the agent runs unhalted until the first successful halt read, and a DEPLOY_RAMP can be accepted first. Fix: treat the halt as unknown, and therefore halted, until the first read.                                                                                                                                                                                                                                             | open   |
| P-M3 | MEDIUM   | new      | Stdin EOF stops the agent, so it exits at once under systemd or nohup; real-mode `calibrate` is only reachable through stdin.                                                                                                                                                                                                                                                                                                                                             | open   |
| P-M4 | MEDIUM   | new      | Camera freshness is stamped after the grab returns, so an old buffered frame reads as fresh; no frozen-frame check. Hardware-dependent (the reviewer is unsure). Fix: buffer size 1 or grab-then-retrieve; compare frame hashes.                                                                                                                                                                                                                                          | open   |
| P-M5 | MEDIUM   | new      | `ModelDetector` drops a NaN-confidence detection (`if not confidence >= min`), so a broken score reads as "nothing detected", contradicting the pipeline's intent. Fix: let NaN fall through so it is treated as unsafe.                                                                                                                                                                                                                                                  | open   |
| P-M6 | MEDIUM   | new      | Any success clears the shared `last_error`, so failing posts with succeeding polls look healthy and link loss never triggers. Fix: track errors per operation class or the time of the last successful post.                                                                                                                                                                                                                                                              | open   |
| P-M7 | MEDIUM   | new      | Status page: POST reads up to 1 MB before the token check; no socket timeout; deep-nested JSON raises `RecursionError` (that request only); the snapshot has no timestamp, so a dead loop still shows the last decision.                                                                                                                                                                                                                                                  | open   |
| P-M8 | MEDIUM   | existing | Responses and pushed events are not authenticated (only requests are signed), `backendUrl` accepts plain http, and a missing secret silently sends unsigned requests, so a forged `halted:false` releases a halt. Fix: require https and a secret in real mode; sign responses; require a fresh authenticated read to release.                                                                                                                                            | open   |
| P-L  | LOW      | mixed    | The decision is computed before the poll (a halt applies one tick, about 200 ms, late); `_accepted` is cleared only in `depart()`; an ack counts as accepted before the backend has it; `maxCameraAgeSeconds` allows up to 60 s; the timeouts default to off with no start-up warning; the camera and serial port are never closed at shutdown; the ESP32 timestamp is ignored (the teammate's module); fixed 2 s reconnect wait; queued reports are dropped at shutdown. | open   |

Sound (per the reviewer): the safety gate (CONTINUE only when the zone is CLEAR and there are no reasons; missing, stale, wrong-typed, NaN or boolean inputs all become halt reasons); the timeout and link-loss reasons only add halts; perception is unsafe by default and a detector exception gives `objects=None`, never an empty list; stale or dead perception ages out after 1 s; the main loop never blocks on the network; **no path writes a camera frame** (recording stores lines and results only); secrets come from the environment and are rejected in config files; the status page binds to loopback, whitelists control values and uses a constant-time token check; signing covers the exact body bytes; real-mode start-up refuses missing sensors and never auto-calibrates. 170 tests pass; nothing has run on hardware.

## Operator console review

| ID   | Severity | Cause | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Status |
| ---- | -------- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| C-H1 | HIGH     | new   | The `?backend=` URL parameter has no allowlist, so a crafted link makes the console send the operator token to another origin (from `sessionStorage`, or typed into the "token needed" form) and show fake data. Fix: accept only the default origin or a configured allowlist; refuse to send the token over plain http or ws to a non-loopback host.                                                                                                                                                                                                              | open   |
| C-H2 | HIGH     | new   | The earlier lost-update fix is incomplete: case, request, telemetry, autonomy and metrics snapshots and the case and request status pushes apply without an ordering check, and `refreshLists` is not guarded by the snapshot generation. A snapshot in flight can put an old case on top of a newer push. Fix: apply only if newer, or buffer pushes during a load.                                                                                                                                                                                                | open   |
| C-H3 | HIGH     | new   | When the button reads "Release halt" the confirmation still asks "Halt deployment on BUS?", and the click sends `halted:false`: the operator thinks they are halting and releases the halt. Fix: build the text from the action's label and pass an explicit halt or release intent.                                                                                                                                                                                                                                                                                | open   |
| C-H4 | HIGH     | new   | A full re-render every 5 s destroys focus and typed input (the token field is wiped within 5 s), closes open dropdowns and re-announces alert banners. Fix: render on data change, update the age text nodes only, preserve focus generically.                                                                                                                                                                                                                                                                                                                      | open   |
| C-M  | MEDIUM   | mixed | A 401 after loading is silent (UI stays "Connected" with stale data); the reducer regresses request status and can leave undefined fields, and one malformed record makes every later render throw; a future device timestamp pins a bus's state; state grows without bound and every render stringifies all of it; one failing bay read aborts the whole snapshot; RESUME asserts `obstacleCleared:true` without showing the operator; `serve.mjs` sends no CSP or frame headers (one-click halt makes clickjacking real) and a malformed URL crashes the process. | open   |
| C-L  | LOW      | mixed | Selector injection in the focus-restore code, prefix checks in `serve.mjs`, hash-route ids with `/`, a startup crash on a bad `backend`, no `aria-modal` or focus trap on the confirm dialog, a reconnect loop with a bad token, "stop undefined" text.                                                                                                                                                                                                                                                                                                             | open   |

Sound (per the reviewer): every interpolation into HTML goes through `esc()`; the token is kept in `sessionStorage` and memory only and never in a URL; passenger identity is dropped from requests; camera frames are never shown; the colour rule holds (shape mark, border style and word on every tag); the reducer does not mutate its input; `serve.mjs` binds to loopback and blocks traversal; 101 tests pass.
