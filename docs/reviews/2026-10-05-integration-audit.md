# Integration audit, 5 Oct 2026

**What this is.** A check of every link in the system, from the passenger app to the operator console, for message shape, signing, ordering, idempotency and failure behaviour. Three read-only audits traced the 11 links through the code and the tests; every finding below was then checked against the code, and the ones in scope were fixed test first (one concern per commit, local commits only, nothing pushed).

**Baseline before the fixes (5 Oct 2026):** `npm run verify` passed 13 of 13 checks. **After the fixes:** `npm run verify` passed 13 of 13 again; the backend suite passed 537 of 537 against a real Postgres; `npm run check:multi-process` and `npm run e2e:scenario:two` passed; the Pi bus agent suite shows 301 passing; the operator console 131.

**Read this first: what "proven" means here.** Every proof below uses simulated sensors, fakes, or a real backend on localhost with simulated agents. **No link has been proven on hardware**, and no test touches a real ESP32, camera, model, laser or physical ramp. Where a row says "proven", it means by a named test in this repository, not on the bus. Hardware claims are made only in `docs/runbooks/hardware-bring-up-handoff.md` and only from output pasted by the hardware session.

How to read the columns: **Status** is in words (proven, partly proven, unproven). **Evidence** names a test or command. **Fix commit** is the local commit that closed a finding (short hash).

## Deferred, with reasons

**Needs a `contracts/` change (not made; propose first):**

1. A simulated flag, or honest fields, on safety telemetry, so fabricated interlocks are labelled by the data and not by words in the console.
2. JSON Schemas for actuator command, actuator status and device health, so those bodies are checked in both languages.
3. A request status for "case over" (today an operator cancel leaves the request `ACKNOWLEDGED`; it is only ignored by the duplicate check, the pulls and the acknowledgement).
4. A separate `deploymentPathClear` meaning: it is false for an operator halt, link loss or waiting for the bay, which the backend then reads as "passenger or object in the path".

**Not in scope for the audit, or owned by someone else:**

5. The passenger app's wording and its dead `api.ts` (the teammate's; ownership ruling).
6. Per-request cancel secret and the shared-record cancel semantics (a design decision).
7. Stale-occupant timeout and force-release of the bay, backend lost-agent detection, backend retract after a failed command (each needs a decision on policy and values).
8. Serial port reopen, camera buffering, the 0.25 confidence floor, a checksum on serial lines: hardware or ML decisions.
9. Console subscription scoping and the console handling of telemetry and actuator pushes.
