# Roadmap: what is still missing (30 Sep 2026)

Scope rule from the project owner: **prioritise software integration between the parts. Testing of the ESP32 and Raspberry Pi hardware, and the machine-learning model running on the Pi, come later.** Everything below can be built and tested on one laptop with simulated sensors. Items that need hardware or the model are listed at the end as deferred.

Sizes are rough: **S** about half a day, **M** one to two days, **L** three days or more. Owners follow `.github/CODEOWNERS`: CE2 is `ry-koh`, teammate is `hongmengsim`.

## Where we are

Done and verified: repository restructured into independent modules with a checker; shared types added (`BusStatus`, `BayStatus`, `RampSafetyDecision`, `RampSimulationStatus`, `HelpRequired`, operator-only message union); line endings fixed; the existing backend, app and ToF module all pass their tests (backend 94, app 420, ToF 10).

Not started: every item below. The backend has no bus, bay, status, acknowledgement or audit endpoints; there is no schema generation; the four planned modules are READMEs only.

## Deferred (per the owner's instruction, and because they need hardware or the model)

- Flashing and testing the ESP32 sketches; running `pi/tof-link` against a real sensor; the physical demo.
- Raspberry Pi bring-up: camera operation, serial permissions, running the agent on the real Pis.
- The perception model on the Pi: NCNN export and benchmark on real frames, lighting and latency tests, covered-camera and dead-sensor robustness runs.
- Machine-learning work in the separate ML repository: labelling, clip-level dataset split, fine-tuning, sealed-set evaluation, inter-labeller agreement, model card.
- Live camera view endpoint and its access control (the console gets a placeholder now).
- Android device testing of the passenger app, including the on-device AI model (needs an ARM64 phone).

## Suggested order

1. **Start in parallel:** B1 to B5 (CE2, backend) and S1 (CE2, pure logic). Both are independent. C1 can start alongside.
2. **Then:** B6, P1, T1, then A1 (needs S1, P1, T1, C1).
3. **Then:** A2, A3, E1, and O1 (independent of A2).
4. **Then:** O2 to O4, R1 to R3, then R4 and R5.

**Milestone: "integrated on one laptop".** E1 passes with two simulated buses, the console shows the full audit trail live, "Confirmed by bus" comes only from a bus, and a halt from the Pi blocks the ramp. No hardware involved.
